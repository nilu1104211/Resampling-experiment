# OUNet 训练后的正式整物体测试

日期：2026-11-05。

本次为公共 `run_subset_eval.py` 补齐 `--models ounet` 与 `--ounet-checkpoint`。加载现有 OUNet-V3 fixed-budget Adapter，直接按 2048→8192 的预算推理；不重训，不增加独立 patch 测试，不为其他已测模型重跑预测。

测试与现有 PUFM、PUFM++、SPU、Ours、Our1 使用相同 PU1K/ModelNet40 各 80 个固定对象、seed=21、7 个条件、canonical 坐标评价和 F-score 阈值 0.01。共 1120 次预测、14 条汇总，默认不启用 P2F，也不需要 PUFM++ 的校准时间表。

OUNet 的固定推理参数为 `octree_depth=8`、`octree_scale=0.25`、`octree_beam=4`。这些参数写入评测 manifest，由入口传给原 Adapter；不使用旧的 scale=0.5 默认值。

## 权重检查

预期服务器权重：`server_runs/patch32/ounet_b8_poly60_scale025_seed21/last.pt`。在服务器运行前置检查确认完成训练，不根据路径名推断完成状态。

前置检查要求：V3、epoch=59、args.epochs=60、model_name=ounet、mixed、非 debug、max_batches=0、depth/scale/beam 与上述一致、poly horizon=60、power=0.9，且保存的调度器已完成 60 轮。公共训练子集指纹和 ModelNet40 冻结数据的哈希继续由公共 preflight 检查。

若权重缺失、未训练到 60 轮，或仍为旧尺度/调试权重，检查会拒绝启动，不会自动训练或更改权重。

## 服务器运行

在 GPU 空闲且 OUNet 训练完成后执行。`--root` 和补充包都使用明确路径，防止沿用终端中错误的变量；参数数组在变量设置后重新创建。

```bash
(
set -euo pipefail
conda activate scdata-v3
cd ~/baseline_compare
git pull --ff-only origin main
source env_v3.sh

if pgrep -af '[r]un_subset_eval.py.*(--models ounet|--worker ounet)'; then
  echo "已有 OUNet 评测进程，请勿重复启动。"
  exit 1
fi

EVAL_OUT="$PWD/server_runs/whole_object_eval80_ounet_20261105"
EVAL_ARGS=(
  --models ounet
  --ounet-checkpoint "$PWD/server_runs/patch32/ounet_b8_poly60_scale025_seed21/last.pt"
  --root "$PWD/adaptive_resampling_data_v3"
  --whole-data-root "$PWD/modelnet40_object80_seed21"
  --objects 80 --seed 21 --device cuda
  --output "$EVAL_OUT"
)

python -u -B run_subset_eval.py "${EVAL_ARGS[@]}" --phase check
mkdir -p "$EVAL_OUT"
nohup python -u -B run_subset_eval.py "${EVAL_ARGS[@]}" --phase run \
  >> "$EVAL_OUT/console.log" 2>&1 < /dev/null &
echo "OUNet 评测已启动，PID=$!"
echo "日志：$EVAL_OUT/console.log"
)
```

前置检查必须通过才会启动后台测试。已完成的同配置条件按完成记录和输出哈希复用；修改代码、权重或配置后输出目录的签名会变化，入口会要求使用新目录。

查看日志：

```bash
tail -f ~/baseline_compare/server_runs/whole_object_eval80_ounet_20261105/console.log
```

`Ctrl+C` 只退出日志查看，后台评测继续。SSH 退出后评测仍可运行。
