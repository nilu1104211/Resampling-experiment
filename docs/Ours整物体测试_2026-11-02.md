# Ours 训练完成后的整物体测试

本入口测试当前训练完成的 RGR + MGB 模型，保留 checkpoint 中保存的配置和原有 `prepare → integrate` 推理路径。它不改变模型、训练数据、推理分块或选模规则。当前使用联合训练 30 轮的末尾权重，不将它称作验证 best。

## 更新代码

新增 `run_subset_eval.py --models ours` 和 `--ours-checkpoint`。原默认模型仍为 PUFM、PUFM++。本机提交推送后，服务器执行：

```bash
conda activate scdata-v3
cd ~/baseline_compare
git pull --ff-only
source env_v3.sh
export CUDA_VISIBLE_DEVICES=0
```

## 检查并测试 Ours

```bash
(
set -euo pipefail
OURS_CKPT="$PWD/server_runs/patch32/ours_rgr_mgb_b8_w0_a8_fused_seed21/full/last.pt"
EVAL_OUT="$PWD/server_runs/whole_object_eval80_ours_20261102"

EVAL_ARGS=(
  --models ours
  --ours-checkpoint "$OURS_CKPT"
  --whole-data-root "$PWD/modelnet40_object80_seed21"
  --objects 80 --seed 21
  --fps-backend cuda --patch-batch-size 1
  --output "$EVAL_OUT"
)

python -u -B run_subset_eval.py "${EVAL_ARGS[@]}" --phase check
python -u -B run_subset_eval.py "${EVAL_ARGS[@]}" --phase run
)
```

- 与原基线测试相同：PU1K、ModelNet40 各 80 个整物体、7 个条件、2048→8192，共 1120 次 Ours 预测；不增加独立局部测试。
- 检查要求权重为 V3、`epoch=29`、非 debug 的 joint 阶段、RGR + MGB 配置，以及 baseline/rgr/gain/joint 训练历史。RGR/GainNet 中间权重或纯基线权重会被拒绝。
- 检查阶段核对训练指纹、数据与 sample ID，不做 GPU 推理或时间表校准。Ours 不需要 PUFM++ 时间表。
- 使用公共 canonical 评价器；GT 只用于事后计算指标，不传给网络。默认不计算需要原网格的 P2F。
- 最终汇总为 `server_runs/whole_object_eval80_ours_20261102/subset_summary.csv`，应有 2 数据集 × 7 条件 = 14 行。每个条件另有逐物体指标、预测、同步计时与日志。
- 相同代码、权重和参数下重跑可复用已完成条件。代码、权重、点数或选样等配置变化后使用新的输出目录，保留旧结果。

## 与纯基线配对测试

如需在同一次运行中重测基线与 Ours，将 `--models ours` 改成 `--models pufm ours`，同时换一个新的输出目录，例如 `server_runs/whole_object_eval80_pufm_ours_20261102`。基线默认使用已完成的独立 30 轮分支 `server_runs/patch32/pufm_baseline_b8_w0_a8_fused/epoch_0030.pt`，也可通过 `--pufm-checkpoint` 指定。

配对测试共 2240 次预测、28 行汇总，两模型由同一抽样与评价代码处理。若使用先前基线结果作比较，应核对对象、条件、数据与推理设置；不能仅凭 CSV 文件名认定它们相同。原始预测和权重不覆盖。

本机已通过 5 项入口检查，覆盖 joint 权重、debug/中间权重拒绝、原基线与 PUFM++ 检查、配置继承及输入接口、共同选样。真实数据另外核对了两个数据集各 80 个物体的选择与基线一致，并验证了 ModelNet40 的 80 个整物体文件哈希；记录为 `outputs/ours_eval_entry_check_20261102.json`。

本轮本机检查不代表读取了服务器训练权重或取得服务器模型成绩，没有运行本轮 GPU 推理。正式结果以服务器检查和实际评测产物为准。
