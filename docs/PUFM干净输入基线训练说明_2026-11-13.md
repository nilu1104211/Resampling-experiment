# PUFM 原始稀疏输入基线训练

## 数据与划分

基线直接读取 PUFM 原始训练加载器使用的 PU1K HDF5，输入为 `poisson_256`，目标为 `poisson_1024`，不添加噪声、孔洞或稀疏退化。每对输入和目标按输入的中心及最大半径做同一归一化。训练保留确定性的随机旋转增强。HDF5 文件可能包含 `addpugan` 数据，具体来源以文件本身为准。

此前审计的文件名为 `pu1k_poisson_256_poisson_1024_pc_2500_patch50_addpugan.h5`，69,000 对数据，SHA256 为 `13888224a5ddb79f59456bd83cf2e997c2da44a313453e4ba27537d27d4ce308`。当前本机没有找到这份原文件，需要先检查服务器上是否存在。每次启动会记录所用 HDF5 的 SHA256，文件不同时不可续训旧输出。

训练使用 HDF5 中的全部训练行，此前文件为 **69,000 个 Patch**。不从 PU1K 训练文件划分验证集。PU1K 官方测试输入和 GT 留作测试，不参与选模。训练 HDF5 没有可靠的物体 ID，是否与官方测试存在重复几何仍需另行核对。

验证使用现有 V3 ModelNet40 Patch 数据的 `A0_normal`，从中固定选 **100 个物体 × 1 个 Patch**，覆盖 40 个类别。名单包含过去已经用于研发对照的 80 个物体及额外选出的 20 个物体，见 `our/PUFM-main/modelnet40_validation_ids.json`。

现有 V3 ModelNet40 Patch 原本来自 ModelNet40 的**官方测试部分**。本实验将其中 100 个物体重新划作验证，剩余 **2,368 个物体**保留为本实验的 ModelNet40 留出集合。因此本实验不能再将完整 2,468 物体称为未用于选模的官方测试集。留出集合中是否还有更早实验使用过的物体，需要按具体实验的名单核对。

ModelNet40 验证使用 V3 从网格生成的干净稀疏点，不对 PU1K 训练输入做重新采样。若有需要，也可以显式用 `--data-source v3` 训练 V3 干净基线，其验证仍是同一 ModelNet40 子集。

## 验证与权重

默认每轮验证全部 100 个验证物体，计算 V3 **canonical 坐标**下的双向 CD-L1，先按物体平均，再对物体等权平均。保存验证 CD-L1 最小的 `best.pt`，`last.pt` 包含最新模型、优化器、RNG 和最优指标，供中断续训。它们会记录 PU1K HDF5 SHA256、完整训练行身份、ModelNet40 名单和验证文件哈希及后端。这里选的是跨数据集验证 CD，测试时还需单独报告 PU1K 表现。

验证只使用观测输入做模型前向，目标仅用于计算指标。基线阶段启用确定性算法，验证会恢复模型状态及随机状态。`--validation-limit` 和 `--max-batches` 仅用于短测，其 checkpoint 被标为调试用途。旧 V3 checkpoint 不能直接作为这一训练的 `--resume`。

## 正式训练

在确认 HDF5 路径后，将以下 `PU1K_H5` 改为实际路径：

```bash
cd /home/zk/baseline_compare
git pull --ff-only origin main
conda activate scdata-v3
export CUDA_VISIBLE_DEVICES=0
export V3_FPS_BACKEND=cuda
PU1K_H5="/替换为实际路径/pu1k_poisson_256_poisson_1024_pc_2500_patch50_addpugan.h5"

mkdir -p server_runs/our2_logs
nohup python -u -B our/PUFM-main/adaptive_v3.py train \
  --stage baseline --preset baseline --data-source pu1k-h5 \
  --pu1k-h5 "$PU1K_H5" --root "$PWD/adaptive_resampling_data_v3" --training-mode clean \
  --epochs 60 --batch-size 8 --workers 0 --assignment-workers 8 \
  --fused-optimizer --seed 21 --device cuda \
  --output "$PWD/server_runs/pufm_official_sparse_seed21" \
  >> server_runs/our2_logs/pufm_official_sparse_seed21.log 2>&1 </dev/null &
echo "PID=$!"
```

每轮验证 100 个 ModelNet40 Patch。使用 `tail -f server_runs/our2_logs/pufm_official_sparse_seed21.log` 查看进度。中断续训时，保持所有数据、训练和输出参数不变，追加 `--resume "$PWD/server_runs/pufm_official_sparse_seed21/last.pt"`。

## ModelNet40 留出集测试

模型训练完成后，使用 `--split modelnet40_holdout --condition A0_normal` 生成剩余 2,368 个物体的预测。配套评估入口也支持同一 `--split modelnet40_holdout`，会校验样本 ID 并自动排除上述 100 个验证物体。原有的 `modelnet40_patch` 依然指完整 2,468 个物体，包含验证集。

```bash
python -u -B our/PUFM-main/adaptive_v3.py predict \
  --root "$PWD/adaptive_resampling_data_v3" \
  --checkpoint "$PWD/server_runs/pufm_official_sparse_seed21/best.pt" \
  --split modelnet40_holdout --condition A0_normal --device cuda \
  --output "$PWD/server_runs/pufm_official_sparse_seed21/modelnet_holdout.npz"

python -u -B tools/evaluate_v3_predictions.py \
  "$PWD/server_runs/pufm_official_sparse_seed21/modelnet_holdout.npz" \
  --root "$PWD/adaptive_resampling_data_v3" \
  --split modelnet40_holdout --condition A0_normal \
  --output "$PWD/server_runs/pufm_official_sparse_seed21/modelnet_holdout_metrics"
```

旧 Our2 诊断入口将旧 PUFM-60 哈希固定在配置中，不能直接使用这个新基线；后续动态分配实验需要新的配置与数据身份。
