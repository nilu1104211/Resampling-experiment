## 结论与适用范围

用户希望统一任务与最终点数，并尽量保留源方法性能。建议采用“统一外部评价任务、保留各方法内部定义、用实验验证适配影响”的原则。

当前共同测试对象、退化条件、2048→8192 和公共评价器可以保留。需要优先处理推理流程与低效采样；SPU-IMR、OUNet 的训练规格也需要在正式训练前重新核对。现有 PUFM、PUFM++ 权重和预测有保留价值，静态差异不能证明训练无效。

“适配不额外削弱源方法”需要同权重对照和实际指标证明。改变数据分布、监督密度或推理定义以后，不能仅凭主干结构不变保证性能不变。

本轮阅读四篇本地 PDF 的相关完整页面，并渲染核验主要实验页面，同时核对作者仓库与本地实现。只新增审查文档；没有修改模型、训练配置、权重、原数据或服务器运行任务。服务器现状与精确性能占比没有直接核验。

### SPU-IMR：2502.19452v1，第 4–5 页，Comparative Study、Implement Details

- 比较方法使用各论文公开代码训练、测试，并区分有监督与自监督。

### OUNet：2410.17001v1，第 5–6 页，4.2–4.4

- OUNet 直接处理整物体，八叉树原生输出点数可变。
- 原任务使用 5000 点输入与 500000 点训练 GT；作者解释，密集 GT 用于缓解构造八叉树时的下采样问题。

- 论文没有把其他所有网络也改成八叉树或相同输出解码器。当前逐层强制选定叶节点数量，是项目新增的方法适配。
- 训练采用 AdamW、poly 学习率衰减；论文设置为 500 轮。作者 YAML 也包含 poly 配置。

### OUNet 需要先解决的兼容边界

原生输出多于 8192 时，可以在完整原生预测后，以固定、仅依赖预测的 FPS 取 8192 点，并记录处理前后点数与耗时。这仍可能改变质量，需要实测。

原生输出少于 8192 时，无法同时满足“原解码不变、逐物体精确 8192、无新增点”。此时不能只把补点隐藏在读取器中。应保留原生结果；如正式主表仍要求精确点数，则预先固定一个不看测试 GT 的输出适配规则，明确标为变体并单独量化影响。现有 BudgetOUNet 可保留为该变体，不能替代原生 OUNet 的定义。

1024 点 GT 构造的八叉树，与密集表面构造的八叉树监督不同。只让 OUNet 使用额外密集 GT，又宣称所有方法使用相同监督预算，也不准确。若提供原生密集监督参考，应限定共同训练物体、披露监督来源和密度，并与严格 V3 统一 GT 的结果区分。

固定尺度会改变有效体素分辨率和占用统计。不能直接将旧权重的 0.5 改成原代码中的 1.7 就视为恢复性能，也不能无条件恢复原裁剪；必须按该权重对应的坐标约定检查覆盖、越界和结果。

## 三、适合当前项目的公平比较协议

1. **固定外部任务。** 保留 PU1K、ModelNet40 各 80 个整物体，7 条件，2048 点共同输入、8192 点共同评价目标，使用相同冻结记录、样本 ID 和 GT。独立局部测试无需新增；网络内部继续允许其原生分块。
2. **保留方法定义。** 主干、原生自监督/有监督目标、分组尺度、迭代恢复、时间表、回投和八叉树占用判定，都按锁定版本处理。必要设备/索引修复可以保留，逐项记录。
3. **按方法保留优化配方。** SPU 使用 cosine，OUNet 使用 poly，PUFM++ 保留阶段划分与时间调度。使用独立验证数据比较收敛，记录更新数、访问样本数与 GPU 小时。不同方法可以有不同轮数，不能根据测试成绩决定加训或选配置。
4. **监督来源透明。** 共同训练物体与退化分布必须一致。若改变训练点数、密集 GT 或采用额外数据，应单独披露；不要把“相同物体”写成“完全相同监督”。SPU 始终保留自监督身份。
5. **内部消融严格配对。** Ours 与 PUFM 基线从同一共同主干分支，匹配主干的后续更新和选模规则；RGR/GainNet/教师数据与训练成本计入 Ours。两边都应使用同一套基础推理封装，确保收益能归因于增强模块。
6. **公开权重独立参考。** 官方预训练结果可用来检查实现能力；核对其训练数据后再解释。V3 留出的 100 个验证物体来自公开训练网格，官方权重可能已经见过；也需要检查测试几何重合。不要把官方额外数据训练的权重与 V3 从头训练模型写成相同训练条件。
7. **固定选模口径。** 当前已完成的末尾权重可先作末尾权重比较。未来若验证选最优，各方法都用相同规则；不能拿 Ours 验证最优与基线最后一轮直接归因网络优劣。

## 四、如何验证适配没有额外削弱源方法

### 先做同权重推理验证

选少量预先固定的验证样本，覆盖正常、噪声、孔洞与离群点。原生路径和适配路径使用同一权重、同一实际输入、同一随机规则及相同输出预算（原生可变点数方法需另记原生结果）。

- 记录归一化、原始输出数量、最终输出数量、有限值与输入覆盖。
- 性能实现等价性：先比较 FPS 选点、KNN 索引与数值差异，再比较完整预测；浮点并列、起点规则和 batch 运算差异需解释。精度误差界限应根据数据尺度与重复运行噪声预先确定。
- 质量验证：比较 CD-L1、平方 CD、HD、F-score；有网格时补 P2F。按物体配对汇总，检查正常条件与退化条件，不能只挑改善的样本。
- 速度验证：GPU 预热后使用同步计时，分别记录预处理/分块、网络、采样/合并、模型端到端和磁盘/指标时间。各方法使用同一硬件和计时范围，保留方法本身合理的批处理。
- 原生流程恢复允许改变已有适配版输出，因此不能称为纯等价加速；应使用新配置签名和独立输出目录。

当前 PUFM++ 静态计数为 24 块×6 步=144 次单块前向；初始化、逐步与最终 FPS 合计约 180248 次 Python 逐点循环，另有 RIN 内部采样。服务器交接日志约 13.4 秒/物体，不能据此确定各算子的占比，也不能承诺优化后达到论文中的时间。

### 然后判断训练是否需要调整

- 先保留并评价现有 PUFM、PUFM++ 权重，优先纠正推理定义与效率。
- EMD 后端和 sum/mean 归约属于训练实现差异，应单独评估；损失缩放在 Adam 下的影响不能简单按缩放倍数推断，静态差异不足以宣布权重无效。
- AdamW 名称本身也不是性能改变的充分证据：当前 PUFM++ 默认 weight decay 为 0，需要结合真实 checkpoint 参数和更新设置判断。
- SPU-IMR、OUNet 当前没有正式训练完成证据，应先把训练规格与源方法的差异处理清楚，再安排长训练。
- 如果最终要证明原生训练协议下的提升，另做明确标记的原生训练复核；不重命名已有 V3 权重来代替这项验证。
