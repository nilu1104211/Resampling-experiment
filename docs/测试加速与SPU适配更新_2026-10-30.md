# 测试加速与 SPU-IMR 适配更新

日期：2026-10-30（北京时间）。修改工作区：`D:/dkwork/baseline_compare`。

## 已完成的修改

### 测试加速

- 用 CUDA FPS 替换 V3 中逐点执行的 Python FPS。通过 PyTorch CUDA 安装附带的 NVRTC 编译，直接在当前 CUDA stream 运行，不需要另外安装 pointops、ninja 或编译 PyTorch C++ 扩展。
- 保留 V3 的最远质心起点、并列选最小索引、已选索引排除规则；匹配连续和通道优先存储的浮点求和顺序。重复点、插值并列距离、非连续张量均有检查。
- PUFM/Ours 的 portable FPS 回退也接入同一个实现。已安装的原生 PUFM pointops 路径继续由原兼容层选择。
- PUFM++ 默认保持 `--patch-batch-size 1`。本轮没有改变时间步、固定分块、局部积分、回投或合并定义；这次解决执行开销，原生推理定义的对齐是另一项工作。
- 可选批处理在本机出现几何输出差异，未设为默认；不能当作已验证等价的正式加速。
- `run_subset_eval.py` 新增 `--fps-backend auto|cuda|torch`，记录实际 FPS 后端与推理配置。`cuda` 模式失败会直接报错，避免悄悄回退后仍以为已经加速。

核心实现：[v3_pointops.py](D:/dkwork/baseline_compare/adaptive_resampling/v3_pointops.py)。

### SPU-IMR

主对比默认改为 `--spu-profile shared-v3`，严格保留共同的训练输入和输出预算。之前给出的 `native` 训练命令已撤回，CLI 和训练损失入口均拒绝再用它进行主对比训练。

1. 与 PUFM、PUFM++ 读取同一份实际 256 点输入、同一份 1024 点 GT、同一训练划分、每物体 32 个基础 patch、同一在线 epoch 退化和共同归一化；不再增加训练观测点数。
2. SPU 保持输入内部的自监督遮挡恢复，不用干净 GT 计算训练损失。GT 形状仍要求为共同的 1024 点，便于数据与评价对齐。
3. 使用 64 组、每组 16 点，保留源方法的观测/分组比例；内部 3 次迭代和默认 8 个恢复序列保持。组邻域可能重叠，不会将组内记录当作额外真实观测。
4. 256 点局部输入最终严格输出 1024 点；2048 点整物体使用内部局部推理和合并，最终严格输出 8192 点。训练与局部推理均使用共同模型坐标，避免额外 bbox 归一化引入训练/推理尺度差异。
5. 保留源恢复 seed、候选密度统计和原近似 EMD 核函数兼容入口；不在密度过滤前去重。最终预测若不足指定数量的不同坐标则报错，不复制点凑数。
6. 保留 cosine 调度，当前 V3 首轮预算统一为 60 轮、预热 5 轮；源 AdamW 初始学习率 1e-3、最低学习率 1e-5、weight decay 0.05 保持。调度器保存并恢复，不能在 resume 时悄悄改变周期。
7. `legacy-patch256` 用于已有旧适配权重；`native` 仅保留历史 1024 点训练实验的推理参考。它们都不能静默作为 `shared-v3` 权重加载或续训。

**公平性边界：** 同输入、同评价点数是主对比约束；SPU 的分组与内部训练目标仍有方法差异。shared-v3 是明确的局部数据适配，不能称为原论文完整复现，也不能凭点数相同保证已充分收敛。

**验证边界：** 现有 `--validation-samples` 是 256 点局部监控，不等于整物体验证选模。正式质量、收敛与选模仍需按确定的验证协议检查。

适配实现：[v3_adapter.py](D:/dkwork/baseline_compare/compare-change/spu-imr-main/v3_adapter.py)；[原 EMD 兼容入口](D:/dkwork/baseline_compare/compare-change/spu-imr-main/source_emd.py)。

## 本机验证证据

环境：RTX 4070 Laptop 8GB、PyTorch 2.5.1+cu121。没有连接服务器。

下列是完整 PUFM++ 网络、真实 PU1K 2048 点整物体、6 步的本机检查。使用随机权重；这是执行耗时与等价性检查，不是模型准确率，也不是服务器速度保证。

| 条件 | 等价 Python FPS 参考路径 | CUDA FPS、单块执行 | 输出检查 |
|---|---:|---:|---|
| A0_normal，2 次 | 12.83 秒/物体 | 3.32 秒/物体 | 逐位相同，约加速 3.9 倍 |
| A0_normal，最终实现复核 2 次 | 27.24 秒/物体 | 4.36 秒/物体 | 逐位相同，约加速 6.2 倍 |
| D2_noise_005，1 次 | 12.76 秒/物体 | 3.32 秒/物体 | 逐位相同 |
| D7_outliers_02 | 不作为稳定测速依据 | 不作为稳定测速依据 | 最终实现逐位一致性通过 |

计时前预热并同步 CUDA；每次对照保持相同网络权重、输入、步数和回投。复核中本机耗时有波动，以上保留原始对照，不将其中某次耗时当作服务器保证。实际训练权重与 RTX 3080 Ti 的复核命令见下文。原生方法的论文计时不能直接替代本项目实测。

- 34 项 V3 数据、路径、优化器、FPS、训练兼容和传输检查通过。
- 7 项 SPU profile、原密度/归一化/RNG 对照、自监督、输出预算、cosine、旧权重隔离、原 EMD 代价与梯度检查通过。
- 4 项比较协议检查、8 项 PUFM/Ours 契约检查通过；合计 53 项。
- 真实 V3 数据另外抽查 5 条基础记录×5 个在线 epoch，共 25 例，SPU、PUFM++ 和 PUFM 基线读者的实际输入、GT、sample ID、training profile 逐位一致。这是实际数据抽查，不是全部 25504 条的穷举。
- shared-v3+source EMD 的真实样本 GPU 前向、反向、一次随机权重优化检查通过；局部 256→1024、整物体 2048→8192 输出通过。没有启动正式训练。
- 上一版 native-1024 检查只作历史记录，不作为主对比训练证据；旧 native 训练 CLI 现已验证会在训练前明确拒绝。
- 原 `compare/`、`baseline/` 目录未修改；既有模型权重、数据和预测未删除。

本机 JSON 记录位于 `outputs/` 下的 `pufmpp_speed*_local_20261030.json`、`spu_shared256_source_smoke_20261030.json`、`spu_shared256_real_data_equality_20261030.json`。这些文件是本机检查记录，不是服务器结果。

## 服务器应用与复核

代码已直接修改在当前 Git 工作区。由用户提交并推送全部相关修改后，服务器通过 Git 拉取更新。

提交时需要包括新增文件，尤其是 `adaptive_resampling/v3_pointops.py`、`compare-change/spu-imr-main/source_emd.py` 和 `tools/profile_v3_inference.py`；同时提交其余修改、测试及本说明。只提交已跟踪文件的修改（例如仅使用 `git commit -am`）会漏掉这些新文件。

本地提交并推送成功后，在旧 GPU 任务结束时更新、测速，避免并发 GPU 任务污染耗时。以下命令不终止旧进程。

```bash
conda activate scdata-v3
cd ~/baseline_compare
git pull --ff-only
source env_v3.sh
```

先用现有 PUFM++ S2 权重及已存在的时间表检查加速前后输出：

```bash
python -u -B tools/profile_v3_inference.py \
  --root "$V3_DATA_ROOT" \
  --checkpoint server_runs/patch32/pufmpp_s2_b8_w0_fused/last.pt \
  --schedule server_runs/whole_object_eval80_20261030/shared_calibration/subset_schedule.pt \
  --samples 2 --repeats 2 \
  --output server_runs/fast_inference_check_20261030.json
```

该命令不训练、不改权重，也不覆盖正式预测。检查 `fast_serial` 的 `last_backend=cuda_nvrtc`、`bitwise_equal=true` 和实际 `mean_seconds`。若单块加速结果未逐位一致，脚本保存记录后报错，应先检查该记录，不直接扩大评测。首次 CUDA 编译与预热不计入所列测量。

通过后，以独立输出目录运行原定各 80 物体、7 条件、两个模型：

```bash
python -u -B run_subset_eval.py \
  --whole-data-root "$PWD/modelnet40_object80_seed21" \
  --fps-backend cuda --patch-batch-size 1 \
  --output server_runs/whole_object_eval80_fast_20261030
```

数据位置沿用用户已经上传的目录。新输出目录重新建立配置签名和一次小训练子集校准，保留旧结果。

SPU 主对比短检查（随机权重，仅检查，不启动长训练）：

```bash
v3 spu-imr smoke --spu-profile shared-v3 --spu-transport source \
  --fps-backend cuda --smoke-object \
  --output server_runs/spu_shared256_source_smoke.json
```

主对比 60 轮训练命令：

```bash
SPU_RUN="$PWD/server_runs/patch32/spu_shared256_b8_w0_cos60_seed21"
mkdir -p "$SPU_RUN"
set -o pipefail
v3 spu-imr train \
  --root "$V3_DATA_ROOT" --device cuda \
  --spu-profile shared-v3 --spu-groups 64 --spu-transport source \
  --fps-backend cuda --training-mode mixed --train-patches-per-object 32 \
  --batch-size 8 --workers 0 --epochs 60 \
  --spu-schedule-epochs 60 --spu-warmup-epochs 5 \
  --lr 1e-3 --weight-decay 0.05 --seed 21 \
  --output "$SPU_RUN" 2>&1 | tee -a "$SPU_RUN/console.log"
```

已有 native-1024/其他周期权重保留为独立实验，不能在该命令上直接加 `--resume` 混用。60 轮是首轮预算，不能根据测试结果反复选择范围，也不能自动称为收敛或 best。
