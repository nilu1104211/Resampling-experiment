# 本机排查与验收记录

日期：2026-11-11。状态：第一版工程实现及小规模真实数据流程通过；尚未完成正式训练与有效性验证。

## 本机确认的事实

1. **监督可用。** 训练 base shard 保存池点、孔洞距离/排序/轴/旋转、GT 对应索引等；训练接口按确定性 seed 在线产生退化及精确来源标签。验证 shard 已保存 `noise_mask_input`、`outlier_mask_input`、`hole_mask_gt`、`selected_pool_index`、`reliability_target_input` 等。实际读取了 train/validation 的样本，监督键齐全。无需先重生成数据。
2. **可靠度是软标签。** `v3_core.corrupt_base` 使用真实扰动位移相对 spacing 的指数衰减，离群点置 0；并非普通噪声二分类标签。新模型保持此定义。
3. **PUFM 接口不同于概念稿。** 原模型是 `forward(query_pts, mid_pts, t)`；没有独立静态 `encode(X)` 和条件参数。原始 Midpoint 在 `models/utils.py`，EMD 的当前 V3 等价精确匹配在 `adaptive_resampling/v3_transport.py`。第一版采用初始化接入，保留原速度场源码。
4. **续训退化不是简单选错 last。** 第二批选模记录选择 epoch 15。验证 Patch CD：原始 B0 `0.04002993775088925`，第 5 轮 `0.040163955928929955`，第 10 轮 `0.04008012312252875`，第 15 轮 `0.03986180244509092`。Patch 最佳但整物体退化，说明跨尺度验证是重要未解决问题。
5. **原续训策略存在可检查差异。** 两批都从同一基线权重开始，重新创建 Adam，数据 epoch 从 0 重计，没有 scheduler，没有有限梯度裁剪，5 轮验证一次且没有 epoch 0 候选。旧 10/15 轮前 10 轮训练损失非常接近，不能将所有差异归因于两个实现完全不同。原基线 checkpoint 保存了 Adam 状态，epoch=29、batch=8、lr=1e-5、797 个训练对象、25504 patches。
6. **采取的工程措施仍待正式比较。** 新流程恢复原 flow Adam 状态、将退化 epoch 从 30 开始、flow LR=1e-6、有限梯度裁剪、epoch 0 和逐轮验证。它们是候选修正，并非已经证明修复了整云退化。

## 已运行的验证

环境：Windows，Python 3.13.3，PyTorch 2.7.1+cu118，NVIDIA GeForce RTX 4070 Laptop GPU。服务器此前环境不同，正式比较必须记录后端/环境。

|---|---|---|
| 5 个单元测试 | 全通过 | 覆盖预算极值/不可行容量、有效梯度、唯一归属、M2 独立性、冻结 BN、配置校验 |
| 原始基线等价 | 逐点精确一致 | 同一本机确定性 Torch 点运算后端 |
| 真实 v3 Patch 的 7 个模块阶段 | 前向、反向、优化一步均通过 | 每阶段只检查一个样本，不评价质量 |
| M1/M2/Joint 的 2048→8192 | 均通过 | 合成输入的尺寸/数值验收，不是整云质量评测 |
| 新模块梯度 | 有限、非零 | M2 独立预算头梯度单独检查，M1 位移门梯度单独检查 |

| 权重保存重载 | 输出逐点精确一致 | 验收用权重明确标记 verification/debug |

初期检测出的 CUDA median 确定性限制已改用排序中位数；预算饱和后的 softmax 下溢通过在剩余可分配区域重新归一化解决。对应边界测试通过。

## 正式实验前仍需解决

- 目前不能宣称 M1/M2/Joint 优于 PUFM，也不能把小预算最优权重当作已训练好的候选模型。
- 续训策略必须在服务器按完整验证预算比较；需要使用训练/验证对象构建独立整云验证，核查 Patch→整云退化，不能拿冻结测试对象反复调参。
- 孔洞候选对自然开口、薄壁和深孔洞的误报/召回尚未测定；预算需求代理也未证明等同于真实增加点数的边际收益。
- 第一版几何编码替代概念稿的静态 PUFM 特征接口；速度场条件注入、复杂拓扑候选、专门的恢复不确定度校准均未加入，应在最小版本有收益后再判断是否必要。
- 最终设计固定后，完成至少 3 seed、独立/联合及内部机制消融、真实整云冻结测试、成对可视化、配对统计和效率比较，再形成论文结论。
